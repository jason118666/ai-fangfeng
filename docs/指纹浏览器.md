# AdsPower 指纹浏览器（可选）

适合想把 Claude 网页版的登录状态、Cookie 和浏览器设置放在专用环境里的人。机场版和自建版都可以配合使用。

**可以增加浏览器数据的隔离，但不能据此认定更不容易封号。** AdsPower 不是 Claude 官方要求，也不能替代代理、防泄露配置或账号本身的安全措施。没有可靠的官方依据证明，使用 AdsPower 能降低 Claude 的封号概率。

## 能把哪些东西放进去

| 使用方式 | AdsPower 能覆盖什么 |
|---|---|
| Claude 网页版 | 在专用环境内完成登录、聊天和账号设置，保留该环境的 Cookie 与登录状态 |
| Google 登录或邮箱登录链接 | 登录过程中尽量在同一环境内完成；涉及邮箱登录时，注意邮箱会话也会成为这个环境中的敏感数据 |
| Claude Code | 浏览器中的授权页面可以在该环境打开，但授权完成后的终端请求仍需单独配置代理 |
| Claude 桌面端、手机端、API 程序 | 不会因为网页端用了 AdsPower 就自动进入它的环境或使用它的代理 |

不需要为了“全部放进去”把日常邮箱、所有账号和密钥都搬进 AdsPower。API 密钥也不要保存到环境备注或截图里。

## 怎么配

1. **先配好网络。** 按 [机场版](机场版.md) 或 [自建版](自建版.md) 完成基础配置，并确认实际使用地点符合 [Claude 支持地区要求](https://support.claude.com/en/articles/8461763-where-can-i-access-claude)。指纹浏览器不会改变服务的地区要求。
2. **从 [AdsPower 官网](https://www.adspower.com/) 下载，创建专用环境。** 例如命名为 `Claude-个人`，长期使用同一个环境，避免误用其他环境的登录状态。
3. **显式设置环境代理。** 本项目使用本机 Clash 时，选择自定义 HTTP 代理，主机填 `127.0.0.1`，端口填 Clash 实际监听的 HTTP / mixed-port，例如 `7892`。不要照抄示例端口，也不要把节点服务器端口填到这里。点击“检查代理”，确认出口符合预期，再打开环境。此配置要求 AdsPower 和 Clash 运行在同一台电脑上。
4. **检查 WebRTC。** 在该环境的指纹设置中选择“禁用 UDP”或禁用 WebRTC，并按下文验证。禁用可能影响音视频功能；仅修改页面展示的 IP 不等于阻止了真实网络流量。
5. **保留稳定、合理的环境设置。** 不需要每次登录都随机生成指纹；浏览器内核及时更新，User-Agent 与内核匹配。拒绝不需要的定位授权，少装扩展。
6. **验证通过后再登录 Claude。** 在该环境打开 `https://claude.ai/`，后续网页操作继续使用该环境。使用邮箱链接登录时，在该环境中打开链接，别误开到系统默认浏览器。

创建环境与代理字段见 [AdsPower 官方说明](https://help.adspower.com/docs/creating_browser_profiles)，WebRTC 选项见 [官方模式说明](https://help.adspower.com/docs/How-to-choose-WebRTC-mode)。具体名称以当前版本为准。

## 怎么验收

先运行仓库检查器，检查本机基础配置：

```powershell
pwsh ./scripts/check.ps1
```

**检查器不会读取 AdsPower 的环境配置。** 它的 WebRTC 项检查的是 Chrome / Edge 策略，即使通过，也不能证明 AdsPower 环境通过。

在 AdsPower 的那个专用环境内手动确认：

- **出口与路由：** 打开 IP 检测页，出口是预期 IP；再访问 Claude，在 Clash 连接记录中核对实际链路，不能是 DIRECT。检测页出口正确不能单独证明 Claude 走了同一条线路。
- **DNS / WebRTC：** 用相应泄露检测页检查，不能暴露本地真实公网 IP 或本地运营商 DNS。DNS 解析器不一定与代理出口处于同一地区，地区不同本身不能直接判定泄露。
- **断线：** 完全退出 Clash，打开一个未缓存的检测页面，必须加载失败，不能回退到本地直连。完成后恢复 Clash。如果配置了其他代理，应停止该环境实际使用的代理服务后再测。
- **终端：** 如果还用 Claude Code，另行验证终端代理及断线行为。浏览器验收不能代替终端验收。

## 登录状态也需要保护

环境中保存的 Cookie 可能让持有者直接使用已登录会话。不要导入陌生人提供的 Cookie，也不要分享含 Claude 登录状态的环境。

个人使用时，检查云同步与团队权限，关闭不需要的 Cookie、密码和本地存储同步，只给必要的人访问权限。AdsPower 官方说明中，环境共享可能包含 Cookie 等数据，云同步会将选中的数据上传到云端，详见 [环境共享](https://help.adspower.com/docs/Profile_Sharing) 和 [全局设置](https://help.adspower.com/docs/global_settings)。

如果只使用一个 Claude 账号，也可以先用普通浏览器的独立用户配置文件整理登录环境，再做好代理和防泄露检查；是否采用 AdsPower，取决于是否需要它额外的环境管理功能。
